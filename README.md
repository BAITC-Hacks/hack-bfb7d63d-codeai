# MoneyMap · HackAlem AI

Банк талдаушысына арналған жергілікті қаржылық байланыстарды зерттеу құралы.

**Ағымдағы жұмыс нұсқасы нақты кейспен тексерілді:** 2 248 клиент, 91 кластер, топ-30; шикі Parquet-тен үш міндетті CSV-ге дейін шамамен 3,6–4,1 секунд. Бағытталған карта, рөлдердің сандық негізі, топаралық ағындар, байланыстырушы клиенттер, бақылау шектеулері, маршруттар, аномалия белгілері және екі стратегиямен түйін алып тастау салыстыруы іске асырылған. Сарапшы CSV арқылы тәуелсіз бағасын қоса алады; көмекші дайын тапсырманы немесе қазақша/орысша шектеулі мәтіндік сұрақты жергілікті есепке айналдырады. OpenAI/NVIDIA адаптерлері бар, нақты ақылы API сұрауы орындалмаған.

Тапсыру нұсқаулығы — [6-кезең](docs/STAGE6.md), бір беттік [архитектура](docs/architecture.html), [5 минуттық демо](docs/DEMO.md), [қазылар сұрақтарына жауаптар](docs/JURY_QA.md). `scripts/verify_submission.py` шикі файлдардан есепті екі рет шығарып, қабылдау шарттары мен уақытты қайта тексереді. `scripts/package_submission.py` жергілікті тапсыру архивтерін жасайды.

ТЗ критерийлері мен қалған шектеулер: [docs/CRITERIA.md](docs/CRITERIA.md). Өзекті тексеру нәтижелері: [docs/VERIFICATION.md](docs/VERIFICATION.md). Алғашқы дерек аудиті тарихи анықтама ретінде [docs/INPUT_AUDIT.md](docs/INPUT_AUDIT.md) ішінде сақталған. Кейс файлдары осы компьютерде `data/case` ішінде бар, Git-ке кірмейді.

## Жергілікті вебті ашу

Windows-та Python **3.12 немесе жаңарақ** және `venv` қажет. Осы жергілікті ортада Python **3.12.14** қолданылады; репозиториймен келген бұрынғы қабылдау журналында Python **3.14.3** көрсетілген. Жаңа ортада тәуелділіктер мен жұмысты қайта тексеру қажет. Python жолда болмаса, орнатылған `python.exe` жолын `-PythonPath` арқылы беріңіз. Скрипттер Python-ды автоматты орнатпайды және жүйелік баптауларды өзгертпейді.

PowerShell ішінде жоба орналасқан папкаға өтіңіз (осы компьютердегі мысал):

```powershell
cd C:\OSPanel\domains\hack-bfb7d63d-codeai
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

`setup.ps1` дайын `.venv` ортасын қайта қолданады; ол болмаса `-PythonPath`, `python`, `python3`, кейін `py -3` нұсқаларын тексереді. Дәл бекітілген тәуелділіктер орнатылған болса, олар қайта орнатылмайды. Мысалы, Python жолын көрсету:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -PythonPath "C:\path\to\python.exe"
```

Мұндағы жолды өз Python орналасуымен ауыстырыңыз. `-PythonPath` жаңа `.venv` жасауға ғана қолданылады; бар орта автоматты ауыстырылмайды.

Браузерде **http://127.0.0.1:8501** ашыңыз. Бірінші орнатудан кейін тек `start.ps1` жеткілікті. Сервер жұмыс істеуі үшін терминалды ашық ұстаңыз; тоқтату — `Ctrl+C`. Егер 8501 порты бос болмаса:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Port 8502
```

Сонда http://127.0.0.1:8502 ашылады. Барлық тәуелділік `requirements.txt` ішінде бекітілген. Алғашқы орнатуға пакеттерді жүктеу үшін интернет қажет болуы мүмкін. Бұрынғы қабылдау журналындағы wheelhouse Windows x64, Python 3.14 үшін дайындалған; өз Python нұсқаңызға және платформаңызға сәйкес wheelhouse қолжетімді болса, пакеттерді интернетсіз орнатыңыз:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -Wheelhouse .\wheelhouse
```

Жеке сынақ ортасы үшін `-VenvDir output\clean-env` қосуға болады; `start.ps1` әдепкі `.venv` ортасын қолданады. Offline жинақ Python-ның өзін қамтымайды; басқа ОС/архитектураға арналған wheel файлдары бөлек қажет. Таза виртуалды ортада `--no-index` арқылы орнату туралы бұрынғы дәлел [STAGE6.md](docs/STAGE6.md) ішінде; бұл ағымдағы компьютерде қайта орындалған сынақ емес. Граф, карта және жергілікті анықтама API-сыз жұмыс істейді; нақты AI сұрауы интернет пен таңдалған провайдердің кілтін қажет етеді. Карта JS/CSS ресурстары жоба ішінде.

macOS/Linux үшін балама:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Бұл платформаларда бөлек тексеру әлі орындалмаған.

## Бірінші рет көру

1. «Демо деректермен тексеру» басыңыз немесе өзіңіздегі үш Parquet файлын бірге жүктеп, «Файлдарды тексеру» басыңыз. «Берілген кейсті ашу» батырмасы `data/case` ішінде үш нақты файл бар кезде ғана көрінеді; репозиторий оларды жеткізбейді.
2. «Рөлдер және басымдық» бөліміне өтіп, «Рөлдер мен басымдықты есептеу» басыңыз. Графты бөлек есептеу міндетті емес.
3. «Тексеру кезегі» ішінен топ-30 клиентті қараңыз. `gid` таңдасаңыз, рөл ережесі, бастапқы сандар және ұпайға қосылған жеті үлес ашылады.
4. «Барлық рөлдер» ішінен рөл бойынша сүзіңіз, «Кластерлер» ішінен топтың клиенттерін көріңіз.
5. «CSV файлдары» арқылы үш міндетті файлды жеке немесе JSON есебімен бірге ZIP түрінде жүктеңіз. Кіріс/шығыс және уақыттық көрсеткіштер «Граф көрсеткіштері» бөлімінде сақталған.
6. «Желі картасы» → «Картаны дайындау» басыңыз. Бұл батырма граф пен рөлдерді қажет болса өзі есептейді. Кез келген толық `gid` енгізіп, «Картадан табу» басыңыз.
7. «Қадам саны» арқылы 1 немесе 2 қадам таңдаңыз. Түйінді басып, төмендегі карточкадан рөл негізін, кіріс/шығысты, көршілерді, жеке операцияларды және seed жолдарын қараңыз. «Таңдалған клиенттің айналасы» картаны сол клиентке ауыстырады.
8. «Карта ауқымы» арқылы толық желіні не бір кластерді ашыңыз; рөл, кластер, жиынтық сома бойынша сүзіңіз. Түстерді рөл/кластер/буын бойынша ауыстыруға болады. Сүзгі тек көрініске әсер етеді, карточка толық бақыланған деректерге сүйенеді.
9. «AI көмекші» → «Көмекшіге деректерді дайындау». «Дайын тапсырма» арқылы клиентті таңдаңыз немесе «Сұрақ жазу» режимінде, мысалы, «Алдымен тексеретін топ 5 клиент» деп жазыңыз. «Сұраққа жауап беру · API-сыз» жергілікті TXT/JSON есеп береді. Толық gid-ті кестеден көшіріңіз. Бұл жалпы чат емес: қолдау бар сұрақтар мен шектеулер [STAGE5.md](docs/STAGE5.md) ішінде.
10. Басқа компьютерде үш Parquet файлын бірге жүктеп, «Файлдарды тексеру» басыңыз. «Демо деректермен тексеру» жасанды мысал үшін қолжетімді.

«Қосымша талдау» → «Қосымша талдауды дайындау» бөлімінде клиент анықтамасы мен маршрут/цикл іздеуін ашыңыз. «Топтар арасындағы ағын» бағытталған кластер жұптарын, сомалар мен байланыстырушы клиенттерді көрсетеді; «Дерек толықтығы» әр клиенттің шектеуі мен келесі дерек сұрауын береді. «Желі тұрақтылығы» → N → «Сценарийді есептеу» басымдық тізімі мен тек seed тізімінен **бірдей санды** клиент алып тастауды салыстырады. Seed — бастапқы тізім; оның бәрі расталған төменгі деңгей емес. Бұл сценарий желінің болашақ қайта құрылуын болжамайды.

### Аномалия белгілері

«Аномалиялар» → «Тексеру параметрлері» → «Үлгілерді есептеу» арқылы төрт ережені іске қосыңыз: ұқсас сомалы қайталаулар, күндік операция санының өсуі, бір күндегі әртүрлі жіберушілер және өз буынындағы көлем ауытқуы. Қажет болса үлгі сома мен пайыздық төзімді беріңіз; олар заңдық шек емес. Күндік орташа барлық бақыланған күндерді, бос күндерді де қамтиды. Шағын топ пен нөлдік салыстыру базасында ұпай жасалмайды. Белгінің толық негізінен нақты сандарды, шартты және өткізіліп кеткен салыстыруларды көріп, CSV/JSON жүктеңіз. Бұл белгілер рөл не кінәлілік ықтималдығы емес.

### Сарапшының бағасы және CSV

1. «Сарапшы бағасы» → «Сарапшы тексеруін дайындау» басыңыз; алғашқы k клиентті немесе бүкіл жиынды таңдаңыз.
2. «Бос тексеру үлгісін жүктеу · CSV» файлын алыңыз. `gid` бағанын мәтін ретінде ашып, `dataset_sha256` және болжам бағандарын сақтаңыз.
3. `reviewed_role` өрісіне алты рөлдің бірін не `unknown`; `investigation_relevant` өрісіне `true`, `false` не `unknown`; `reviewer_note` өрісіне негіздеме енгізіңіз. Жүйе өз болжамын сарапшы жауабы ретінде толтырмайды.
4. Толтырылған CSV-ді жүктеп, «CSV белгілерін қолдану» басыңыз. Басқа деректер жиынының файлы қабылданбайды. Бір клиентті интерфейсте жеке бағалауға да болады.
5. Accuracy, macro F1 және қателер матрицасы тек белгілі рөлмен бағаланған іріктемеге қатысты. Толық precision@k алғашқы k клиенттің қажеттілігі түгел бағаланғанда ғана беріледі; әйтпесе қамтылу, бағаланғандар үлесі және мүмкін аралық көрсетіледі.

Белгілер сессия жадында сақталады: шықпас бұрын «Сақталған белгілерді жүктеу · CSV» басыңыз. Бір жиындағы рөлді қайта есептеу белгілерді сақтайды; дерек өзгерсе тазалайды. Бұл жұмыс процесі толық ground truth базасын немесе калибрленген модельді алмастырмайды.

Деректер ауысқанда граф, рөл, карта, қосымша талдау, аномалиялар, сарапшы белгілері және AI нәтижелері тазартылады. Графты қайта есептеу ескі рөлдер мен оларға тәуелді нәтижелерді; рөлдерді қайта есептеу карта, қосымша талдау, аномалиялар және AI күйін жаңартуды талап етеді. Бір деректер жиынына қатысты сарапшы белгілері рөлдерді қайта есептегенде сақталады. Карта нұсқаулығы: [docs/STAGE4.md](docs/STAGE4.md).

Сол жақтағы «Демо файлдарын жүктеу» батырмасы ZIP береді. Оны ашып, ішіндегі үш Parquet файлын қайта жүктеу арқылы толық жүктеу сценарийін сынауға болады. Демо толығымен жасанды: 16 клиент, 15 байланыс, 17 операция. Бұл нақты кейс және рөлдер туралы дайын жауап емес.

## Қабылданатын деректер

| Файл | Міндетті бағандар |
|---|---|
| `nodes.parquet` | `gid`, `depth`, `is_seed` |
| `edges.parquet` | `src`, `dst`, `sum_kzt`, `n_tx`, `depth` |
| `transactions.parquet` | `src`, `dst`, `date`, `sum_kzt` |

Әр файл үшін жүктеу шегі — 20 МБ. Кіріс деректері сервер жадында өңделеді; веб жүктемелер дискіге автоматты түрде сақталмайды. Шикі файлдар өзгертілмейді. Граф, рөлдер, карта және жергілікті анықтама API-сыз орындалады. AI қосылса, тек арнайы батырма таңдаған қысқаша көрсеткіштерді провайдерге жібереді.

Тексеру мына жағдайларды қамтиды:

- файлдың Parquet ретінде оқылуы, міндетті және қайталанатын бағандар;
- бос мәндер, дәл бүтін int64 идентификаторлар, `depth` аралығы, `is_seed` мәндері;
- қайталанатын `gid` және `src → dst` жұптары;
- `nodes` ішінде жоқ аударым қатысушылары;
- сомалардың оң және шекті болуы, операция санының бүтін болуы;
- күндердің оқылуы және транзакцияларды жұп бойынша қосқанда `edges` сомалары/санына сәйкестігі;
- деректердің шектеулері: 4-буын, толық емес seed кірістері, байланысы жоқ seed, шығыстың көрінетін кірістен артық болуы, кезең және 5 000 ₸ шегі.

Қателер талдауға дайын күйге өтуге кедергі болады. Ескертулер бақыланатын үзіндінің шектеулерін түсіндіреді. Оқылған жолдар жасырын түрде жойылмайды немесе біріктірілмейді. Ұйымдастырушы README бойынша `nodes.depth` — клиент алғаш табылған буын (0–4), `edges.depth` — байланыс табылған қадам (1–4). Екеуі графта бөлек сақталады; жалпы валидатор `edges.depth` үшін 0–4 аралығын қабылдайды.

## Нақты кейспен тексеру

Берілген файлдарда **2 248 клиент, 3 119 байланыс, 4 840 операция, 81 seed** бар. Бағытты уақытша ескермегенде 35 байланысқан бөлік, оның 19-ы оқшау клиент; ең үлкен бөлікте 1 877 клиент. Бақыланған айналым — **365 890 012,01 ₸**, кезең — 2026-07-01–2026-07-31. Ағымдағы есеп: 91 кластер, топ-30, негізгі CSV-ге дейін шамамен 3,6–4,1 секунд. Бұл уақыт орта орнатуды, браузерді және кеңейтілген есептерді қамтымайды; әр іске қосудың нақты уақыты `run_report.json` ішінде.

Әдепкі қосымша есепте 212 бағытталған кластер жұбы, 385 байланыстырушы кандидат және 247 аномалия белгісі табылды: 41 ұқсас сома, 140 күндік өсу, 66 күндік көп жіберуші. Бұл 247 бірегей клиент не расталған бұзушылық деген сөз емес. Циклдер есебі 100 жолмен, уақыттық маршруттар анықталған 274 үлгінің 100-імен шектелген; іздеу шектері есепте көрсетіледі. Қайта тексеру дәлелі: [VERIFICATION.md](docs/VERIFICATION.md).

Көрсеткіштер мен формулалар: [docs/STAGE2.md](docs/STAGE2.md). Браузерде ұзын `gid` мәтін ретінде беріледі. CSV файлдарын Excel-ге импорттағанда да `gid` бағанын мәтін түрінде таңдаңыз.

**API-ды кейін қосу:** `.env.example` үлгісінен жергілікті `.env` жасаңыз; бар файлды үстінен жазбаңыз. `OPENAI_API_KEY` немесе `NVIDIA_API_KEY` енгізіп, `MONEYMAP_AI_ENABLED=true` орнатыңыз. «AI көмекші» ішіндегі провайдерді таңдап, «API күйін жаңарту» басыңыз; сұрау тек «AI түсіндірмесін алу» арқылы жіберіледі. Толық нұсқаулық: [docs/STAGE5.md](docs/STAGE5.md).

Әдепкі лимит: жоба бойынша 20 сұрау, 200 000 есепке алынған/резервтелген токен, OpenAI үшін $1 есептік шығын. Бұл аккаунттағы кредит қалдығы немесе провайдердің төлем шегі емес. NVIDIA құны белгісіз болғандықтан оған ақша сомасы болжанбайды; сұрау/токен шектері қолданылады. Кілттер браузерге және журналға жазылмайды; толық gid орнына C001 сияқты белгілер жіберіледі. Модель үйретілмейді, екі провайдер қатар шақырылмайды.

Модельдер: OpenAI `gpt-4.1-mini-2025-04-14`, NVIDIA API Catalog `meta/llama-3.3-70b-instruct`. Модель атаулары бекітілген; өзге NVIDIA сервисінің токені болса, интеграцияны бөлек нақтылау қажет. API жауабының қазақша сапасы және осы аккаунттардағы қолжетімділік нақты кілтпен әлі тексерілген жоқ.

## Командалық жолдағы тексеру

**Бір команда: шикі Parquet → ТЗ-дегі үш CSV**, қажет болса жергілікті орта мен тәуелділіктерді дайындаумен бірге. Деректер `data/case` ішінде болуы керек; басқа орналасу үшін `-DataDir` мәнін өзгертіңіз:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -DataDir data/case -Out output/submission/results
```

Жолында бос орын болса, тырнақша қолданыңыз. Салыстырмалы жолдар жоба папкасынан есептеледі. Алғашқы іске қосуға қажет болса `-PythonPath "C:\path\to\python.exe"` қосыңыз. Дайын ортада скрипт тәуелділіктерді тексереді және бар CLI-ді шақырады. Тікелей балама: `.\.venv\Scripts\python.exe -m moneymap run --data-dir data/case --out output/submission/results`.

Шығыс:

- `nodes_roles.csv`: gid, role, role_score, cluster_id, priority_score, evidence — әр клиентке бір жол;
- `clusters.csv`: cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis;
- `top_nodes.csv`: rank, gid, role, priority_score, why — әдепкі топ-30;
- `run_report.json`: нақты ережелер, шектер, салмақтар, нормалау мәндері, кіріс SHA-256, кітапхана нұсқалары және CSV-ге дейінгі уақыт.

`run.ps1 -TopN 50` (CLI: `--top-n 50`) тізімді ұзартады; ең азы 20. Егер жиында 20-дан аз клиент болса (демода 16), барлығы беріледі. `-Config config/roles.json` (CLI: `--config`) арқылы шектерді беруге болады; белгісіз параметрлер мен жарамсыз мәндер қабылданбайды. Қайта іске қосу осы есеп файлдарын жаңартады. `raw_to_csv_seconds` орта орнату уақытын және қосымша интерактивті іздеулерді қамтымайды.

Кеңейтілген есептерді қосу:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1 -DataDir data/case -Out output/submission/results -Extended
# Дайын ортадағы тікелей балама:
.\.venv\Scripts\python.exe -m moneymap run --data-dir data/case --out output/submission/results --extended
```

Үш негізгі CSV өзгермейді. `extended/` қалтасына **12 қосымша файл** жазылады: `cluster_flows.csv`, `bridge_nodes.csv`, `node_coverage.csv`, `data_requests.csv`, `cycles.csv`, `reciprocal_pairs.csv`, `repeated_routes.csv`, `resilience.csv`, `removal_strategies.csv`, `anomalies.csv`, `expert_review_template.csv`, `extended_report.json`. JSON параметрлерді, шектеулерді және хэштерді сақтайды; сарапшы үлгісі бағаланбаған күйде беріледі. Вебте «Қосымша талдау» → «Қосымша есептердің бәрін дайындау» → «Қосымша есептер · ZIP» осы жинақты береді. Бұл жинақ әдепкі параметрлермен жасалады; экранда өзгертілген аномалия параметрлері үшін сол бөлімнің жеке CSV/JSON жүктеуін пайдаланыңыз.

Рөлдердің әдепкі критерийлері төмендегі ретпен тексеріледі. 4-буын, оқшау және тек өзіне аударымы бар клиент алдымен `peripheral` болады. Seed клиенттеріне қатынасқа сүйенген рөл берілмейді. Жіберуші/алушы саны тек **өзге бірегей клиенттерді** санайды; өзіне аударым графта, сомада және операция санында сақталады. Өзіне ғана аударымы бар клиент оқшау деп саналмайды.

| Рөл | Формалды ереже |
|---|---|
| coordinator | кіріс көрші ≥3, шығыс көрші ≥3, жететін өзге seed ≥2, аралық орталықтық >0 және оң мәндердің P90 шегінен кем емес |
| distributor | бірегей алушылар ≥10 |
| consolidator | қатынас жарамды, жіберушілер ≥5, көрінетін шығыс/кіріс ≤0.3 |
| transit | қатынас жарамды, екі бағыт бар, көрінетін шығыс/кіріс 0.8–1.2 |
| terminal | қатынас жарамды, кіріс >0, өзге клиентке шығыс байланысы жоқ; осы кезеңдегі бақылау ғана |
| peripheral | алдыңғы ережелер орындалмаған немесе дерек жеткіліксіз |

`role_score` — түсіндірілетін ережеге сәйкестік ұпайы, калибрленген ықтималдық емес. `priority_score` одан бөлек жеті белгіден есептеледі: жинақталу 25%, кіріс сомасы 15%, жіберушілер 15%, аралық орталықтық 15%, seed-ден жету 15%, алушылар 10%, PageRank 5%. Нормалау, барлық ұпай формуласы, кластерлеу және шектеулер: [docs/STAGE3.md](docs/STAGE3.md). Рөл анықтайтын ережелер де, сандық нәтижелер де кінәлілікті анықтамайды.

Жасанды файлдар жасау (бар файлдарды үстінен жазбайды):

```powershell
.\.venv\Scripts\python.exe -m moneymap demo --output-dir data/demo
```

Бір командамен тексеру есебін алу:

```powershell
.\.venv\Scripts\python.exe -m moneymap validate --data-dir data/demo --output output/validation_report.json
```

Шығу коды: `0` — сәтті; `1` — деректерді тексеру қатесі; `2` — команда, конфигурация, файл немесе есептеу қатесі. `validate` тек бірінші кезеңнің тексеру есебін береді; `run` үш міндетті CSV шығарады. Жарамсыз кіріс анықталса, жаңа есеп жазылмайды; бұрынғы шығыс файлдары болса, олар өзгеріссіз қалады.

Граф пен 2-кезеңнің төрт есебін бір командамен алу:

```powershell
.\.venv\Scripts\python.exe -m moneymap analyze --data-dir data/case --out output/stage2
```

Нәтиже: `node_metrics.csv`, `components.csv`, `daily_activity.csv`, `graph_summary.json`. Команда алдымен деректерді тексереді; жарамсыз жиынға есеп шығармайды. Қайта іске қосқанда осы төрт есеп жаңартылады. Кіріс файлдары өзгертілмейді.

Тесттер:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

## Шамамен 1 миллион түйінге масштабтау жоспары

Қазіргі тексеру 2 248 түйіндік кейске қатысты. Миллион түйінде жылдамдық не жад көлемі өлшенген жоқ; төмендегі өзгерістер әлі іске асырылмаған.

| Қазіргі шектеу | Үлкен дерек үшін өзгеріс | Нені тексеру керек |
|---|---|---|
| Үш кесте түгел Pandas жадына оқылады; NetworkX әр түйін/қырды Python объектісімен сақтайды | Parquet-тен тек қажет бағандарды блокпен оқу; жұптық сомаларды бағандық қозғалтқышта есептеу; графты ықшам CSR массивінде сақтау | int64 gid дәлдігі, сомалар мен операциялардың сақталуы, оқшау түйіндердің жоғалмауы |
| Салмақсыз дәл betweenness толық графта шамамен O(V×E) жұмыс істейді | Бекітілген seed-пен түйіндерді іріктеп жуық орталықтық есептеу немесе тек тексерілетін ішкі графта есептеу | Кіші эталонда дәл нәтижемен салыстыру; жуықтық пен рейтинг ауытқуын есепке жазу |
| Әр seed үшін бағытталған жетуді есептеу seed саны өскенде қымбаттайды | Қолжетімділікті компонент/партия бойынша есептеу, bitmap сақтау; карточка жолдарын сұрау бойынша алу | Қолданылған шектеулерді көрсету; жету саны мен толық ақша қозғалысын шатастырмау |
| Louvain және толық граф бір процесс ішінде есептеледі | Ықшам граф қозғалтқышында партиялық қауымдастық есептеу; уақыт бойынша snapshot сақтау | Кластерлердің тұрақтылығы, нұсқаланған параметрлер және ережелермен үйлесуі |
| Қазіргі толық карта бүкіл payload-ты браузерге береді | Серверден gid бойынша 1–2 қадамдық ішкі граф, беттелген көршілер; көрсетілген/толық санды бөлек беру | Миллион түйінді браузерге жібермеу; сүзгі карточканың бастапқы сандарын өзгертпеуі |

Алдымен CPU мен RAM өлшеніп, 10 мың → 100 мың → 1 миллион түйіндік жүктеме сынағы жүргізіледі. GPU кейін өлшенген қажеттілік болса ғана қосылады. **NVIDIA API токені жергілікті GPU жадын немесе граф есептеу кластерін бермейді**: қазіргі интеграция оны тек тілдік түсіндірме үшін қолданады. Қазіргі прототипте жеке ML моделін үйрету қажет емес; болашақ бақыланатын модель үшін белгіленген нәтижелер, уақыт бойынша бөлінген бағалау және дерек ағуын тексеру керек.

Фондық есептеу, кіріс хэші/конфигурация бойынша кэш және жад, детерминизм, топ-N тұрақтылығын өлшеу реті [ARCHITECTURE.md](docs/ARCHITECTURE.md) ішінде.
