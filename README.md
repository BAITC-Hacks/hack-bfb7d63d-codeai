# MoneyMap · HackAlem AI

Банк талдаушысына арналған жергілікті қаржылық байланыстарды зерттеу құралы.

**Ағымдағы нәтиже: 1–4 және 6-кезең дайын, 5-кезеңнің кілтсіз нұсқасы дайын.** Деректер тексеріледі, барлық клиенті бар граф құрылады, алты рөлдің болжамы, Louvain кластерлері, тәуелсіз тексеру басымдығы және ТЗ-дегі үш CSV есептеледі. Интерактивті карта мен толық карточка бар. AI көмекшіге арналған бес тапсырма, жергілікті анықтама, OpenAI/NVIDIA адаптерлері және шығын есебі қосылды. Пайдаланушы сұрауы бойынша нақты API қосылмаған: провайдерлер имитацияланған жауаптармен тексерілді. Нақты кейс деректері Git-ке енгізілмеген.

Тапсыру нұсқаулығы — [6-кезең](docs/STAGE6.md), бір беттік [архитектура](docs/architecture.html), [5 минуттық демо](docs/DEMO.md), [қазылар сұрақтарына жауаптар](docs/JURY_QA.md). `scripts/verify_submission.py` шикі файлдардан есепті екі рет шығарып, қабылдау шарттары мен уақытты қайта тексереді. `scripts/package_submission.py` жергілікті тапсыру архивтерін жасайды.

Ұйымдастырушының Downloads ішіндегі нақты үш Parquet файлы кейін қаралып, 1-кезең валидаторынан және браузердегі жүктеу сценарийінен өтті. Материалдардың мақсаты, расталған сандар мен starter шектеулері: [docs/INPUT_AUDIT.md](docs/INPUT_AUDIT.md).

## Жергілікті вебті ашу

Windows PowerShell ішінде жоба папкасына өтіңіз:

```powershell
cd D:\OSPanel\domains\hack-bfb7d63d-codeai
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Браузерде **http://127.0.0.1:8501** ашыңыз. Бірінші орнатудан кейін тек `start.ps1` жеткілікті. Сервер жұмыс істеуі үшін терминалды ашық ұстаңыз; тоқтату — `Ctrl+C`. Егер 8501 порты бос болмаса:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Port 8502
```

Сонда http://127.0.0.1:8502 ашылады. Тексерілген орта — Windows x64, Python 3.14.3; барлық тәуелділік `requirements.txt` ішінде бекітілген. Негізгі ZIP үшін алғашқы орнату интернетті қажет етеді. Offline ZIP ішіндегі `wheelhouse` дайын болса, Python 3.14 x64 орнатылған компьютерде пакеттерді интернетсіз орнатыңыз:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -Wheelhouse .\wheelhouse
```

Жеке сынақ ортасы үшін `-VenvDir output\clean-env` қосуға болады; `start.ps1` әдепкі `.venv` ортасын қолданады. Offline жинақ Python-ның өзін қамтымайды; басқа ОС/архитектураға арналған wheel файлдары бөлек қажет. Таза виртуалды ортада `--no-index` арқылы орнату тексерілді. Граф, карта және жергілікті анықтама API-сыз жұмыс істейді; нақты AI сұрауы интернет пен таңдалған провайдердің кілтін қажет етеді. Карта JS/CSS ресурстары жоба ішінде.

macOS/Linux үшін балама:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

Бұл платформаларда бөлек тексеру әлі орындалмаған.

## Бірінші рет көру

1. Осы компьютерде «Берілген кейсті ашу» басыңыз. Батырма `data/case` ішінде үш файл бар кезде көрінеді. Ұйымдастырушы файлдарының жергілікті көшірмесі дайын; бастапқы файлдар өзгертілмеген.
2. «Рөлдер және басымдық» бөліміне өтіп, «Рөлдер мен басымдықты есептеу» басыңыз. Графты бөлек есептеу міндетті емес.
3. «Тексеру кезегі» ішінен топ-30 клиентті қараңыз. `gid` таңдасаңыз, рөл ережесі, бастапқы сандар және ұпайға қосылған жеті үлес ашылады.
4. «Барлық рөлдер» ішінен рөл бойынша сүзіңіз, «Кластерлер» ішінен топтың клиенттерін көріңіз.
5. «CSV файлдары» арқылы үш міндетті файлды жеке немесе JSON есебімен бірге ZIP түрінде жүктеңіз. Кіріс/шығыс және уақыттық көрсеткіштер «Граф көрсеткіштері» бөлімінде сақталған.
6. «Желі картасы» → «Картаны дайындау» басыңыз. Бұл батырма граф пен рөлдерді қажет болса өзі есептейді. Кез келген толық `gid` енгізіп, «Картадан табу» басыңыз.
7. «Қадам саны» арқылы 1 немесе 2 қадам таңдаңыз. Түйінді басып, төмендегі карточкадан рөл негізін, кіріс/шығысты, көршілерді, жеке операцияларды және seed жолдарын қараңыз. «Таңдалған клиенттің айналасы» картаны сол клиентке ауыстырады.
8. «Карта ауқымы» арқылы толық желіні не бір кластерді ашыңыз; рөл, кластер, жиынтық сома бойынша сүзіңіз. Түстерді рөл/кластер/буын бойынша ауыстыруға болады. Сүзгі тек көрініске әсер етеді, карточка толық бақыланған деректерге сүйенеді.
9. «AI көмекші» → «Көмекшіге деректерді дайындау» → тапсырма/клиент таңдаңыз → «Жергілікті есепті ашу · API-сыз» басыңыз. Анықтаманы TXT және фактілерді JSON түрінде алуға болады. Кілтсіз AI батырмасы өшірулі тұрады.
10. Басқа компьютерде үш Parquet файлын бірге жүктеп, «Файлдарды тексеру» басыңыз. «Демо деректермен тексеру» жасанды мысал үшін қолжетімді.

Деректер ауысқанда алдыңғы граф, рөл есебі және карта таңдауы тазартылады. Графты қайта есептеу ескі рөлдер мен картаны, рөлдерді қайта есептеу картаны тазалайды. Карта нұсқаулығы мен сүзгілердің нақты мағынасы: [docs/STAGE4.md](docs/STAGE4.md). Толық желі жалпы шолу үшін; нақты байланысты оқу үшін клиенттің 1–2 қадамдық айналасын ашыңыз.

Сол жақтағы «Демо файлдарын жүктеу» батырмасы ZIP береді. Оны ашып, ішіндегі үш Parquet файлын қайта жүктеу арқылы толық жүктеу сценарийін сынауға болады. Демо толығымен жасанды: 16 клиент, 15 байланыс, 17 операция. Бұл нақты кейс және рөлдер туралы дайын жауап емес.

## Қабылданатын деректер

| Файл | Міндетті бағандар |
|---|---|
| `nodes.parquet` | `gid`, `depth`, `is_seed` |
| `edges.parquet` | `src`, `dst`, `sum_kzt`, `n_tx`, `depth` |
| `transactions.parquet` | `src`, `dst`, `date`, `sum_kzt` |

Әр файл үшін жүктеу шегі — 20 МБ. Кіріс деректері сервер жадында өңделеді; веб жүктемелер дискіге автоматты түрде сақталмайды. Шикі файлдар өзгертілмейді. Граф, рөлдер, карта және жергілікті анықтама API-сыз орындалады. AI қосылса, тек арнайы батырма таңдаған қысқаша көрсеткіштерді провайдерге жібереді.

Тексеру мына жағдайларды қамтиды:

- файлдың Parquet ретінде оқылуы, міндетті және қайталанатын бағандар;
- бос мәндер, дәл бүтін int64 идентификаторлар, `depth` аралығы, `is_seed` мәндері;
- қайталанатын `gid` және `src → dst` жұптары;
- `nodes` ішінде жоқ аударым қатысушылары;
- сомалардың оң және шекті болуы, операция санының бүтін болуы;
- күндердің оқылуы және транзакцияларды жұп бойынша қосқанда `edges` сомалары/санына сәйкестігі;
- деректердің шектеулері: 4-буын, толық емес seed кірістері, байланысы жоқ seed, шығыстың көрінетін кірістен артық болуы, кезең және 5 000 ₸ шегі.

Қателер талдауға дайын күйге өтуге кедергі болады. Ескертулер бақыланатын үзіндінің шектеулерін түсіндіреді. Оқылған жолдар жасырын түрде жойылмайды немесе біріктірілмейді. Ұйымдастырушы README бойынша `nodes.depth` — клиент алғаш табылған буын (0–4), `edges.depth` — байланыс табылған қадам (1–4). Екеуі графта бөлек сақталады; жалпы валидатор `edges.depth` үшін 0–4 аралығын қабылдайды.

## Екінші кезеңнің нәтижесі

Нақты кейс: **2 248 клиент, 3 119 байланыс, 4 840 операция, 81 seed**. Бағытты уақытша ескермегенде 35 байланысқан бөлік бар, оның 19-ы оқшау клиент. Ең үлкен бөлікте 1 877 клиент. Бақыланған айналым — **365 890 012,01 ₸**, кезең — 2026-07-01–2026-07-31.

Көрсеткіштер мен формулалар: [docs/STAGE2.md](docs/STAGE2.md). Браузерде ұзын `gid` мәтін ретінде беріледі. CSV файлдарын Excel-ге импорттағанда да `gid` бағанын мәтін түрінде таңдаңыз.

**API-ды кейін қосу:** `.env.example` үлгісі мен осы компьютерде Git-тен шығарылған `.env` дайын. `OPENAI_API_KEY` немесе `NVIDIA_API_KEY` енгізіп, `MONEYMAP_AI_ENABLED=true` орнатыңыз. «AI көмекші» ішіндегі провайдерді таңдап, «API күйін жаңарту» басыңыз; сұрау тек «AI түсіндірмесін алу» арқылы жіберіледі. Толық нұсқаулық: [docs/STAGE5.md](docs/STAGE5.md).

Әдепкі лимит: жоба бойынша 20 сұрау, 200 000 есепке алынған/резервтелген токен, OpenAI үшін $1 есептік шығын. Бұл аккаунттағы $50 кредиттің қалдығы немесе провайдердің төлем шегі емес. NVIDIA құны белгісіз болғандықтан оған ақша сомасы болжанбайды; сұрау/токен шектері қолданылады. Кілттер браузерге және журналға жазылмайды; толық gid орнына C001 сияқты белгілер жіберіледі. Модель үйретілмейді, екі провайдер қатар шақырылмайды.

Модельдер: OpenAI `gpt-4.1-mini-2025-04-14`, NVIDIA API Catalog `meta/llama-3.3-70b-instruct`. Модель атаулары бекітілген; өзге NVIDIA сервисінің токені болса, интеграцияны бөлек нақтылау қажет. API жауабының қазақша сапасы және осы аккаунттардағы қолжетімділік нақты кілтпен әлі тексерілген жоқ.

## Командалық жолдағы тексеру

**Бір команда: шикі Parquet → ТЗ-дегі үш CSV.** Деректер `data/case` ішінде болуы керек; басқа орналасу үшін `--data-dir` мәнін өзгертіңіз.

```powershell
.\.venv\Scripts\python.exe -m moneymap run --data-dir data/case --out output/submission/results
```

Шығыс:

- `nodes_roles.csv`: gid, role, role_score, cluster_id, priority_score, evidence — әр клиентке бір жол;
- `clusters.csv`: cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis;
- `top_nodes.csv`: rank, gid, role, priority_score, why — әдепкі топ-30;
- `run_report.json`: нақты ережелер, шектер, салмақтар, нормалау мәндері, кіріс SHA-256, кітапхана нұсқалары және CSV-ге дейінгі уақыт.

`--top-n 50` тізімді ұзартады; ең азы 20. Егер жиында 20-дан аз клиент болса (демода 16), барлығы беріледі. `--config config/roles.json` арқылы шектерді беруге болады; белгісіз параметрлер мен жарамсыз мәндер қабылданбайды. Қайта іске қосу осы есеп файлдарын жаңартады.

Рөлдердің әдепкі критерийлері төмендегі ретпен тексеріледі. 4-буын, оқшау және тек өзіне аударымы бар клиент алдымен `peripheral` болады. Seed клиенттеріне қатынасқа сүйенген рөл берілмейді.

| Рөл | Формалды ереже |
|---|---|
| coordinator | кіріс көрші ≥3, шығыс көрші ≥3, жететін өзге seed ≥2, аралық орталықтық >0 және оң мәндердің P90 шегінен кем емес |
| distributor | бірегей алушылар ≥10 |
| consolidator | қатынас жарамды, жіберушілер ≥5, көрінетін шығыс/кіріс ≤0.3 |
| transit | қатынас жарамды, екі бағыт бар, көрінетін шығыс/кіріс 0.8–1.2 |
| terminal | қатынас жарамды, кіріс >0, шығыс байланысы 0; осы кезеңдегі бақылау ғана |
| peripheral | алдыңғы ережелер орындалмаған немесе дерек жеткіліксіз |

`role_score` — түсіндірілетін ережеге сәйкестік ұпайы, калибрленген ықтималдық емес. `priority_score` одан бөлек жеті белгіден есептеледі: жинақталу 25%, кіріс сомасы 15%, жіберушілер 15%, аралық орталықтық 15%, seed-ден жету 15%, алушылар 10%, PageRank 5%. Нормалау, барлық ұпай формуласы, кластерлеу және шектеулер: [docs/STAGE3.md](docs/STAGE3.md). Рөл анықтайтын ережелер де, сандық нәтижелер де кінәлілікті анықтамайды.

Жасанды файлдар жасау (бар файлдарды үстінен жазбайды):

```powershell
.\.venv\Scripts\python.exe -m moneymap demo --output-dir data/demo
```

Бір командамен тексеру есебін алу:

```powershell
.\.venv\Scripts\python.exe -m moneymap validate --data-dir data/demo --output output/validation_report.json
```

Шығу коды: `0` — сәтті; `1` — деректерді тексеру қатесі; `2` — команда, конфигурация, файл немесе есептеу қатесі. `validate` тек бірінші кезеңнің тексеру есебін береді; `run` үш міндетті CSV шығарады. Жарамсыз кіріс анықталса, жаңа есеп жазылмайды; бұрынғы шығыс файлдары болса, олар өзгеріссіз қалады.

Граф пен 2-кезеңнің төрт есебін бір командамен алу:

```powershell
.\.venv\Scripts\python.exe -m moneymap analyze --data-dir data/case --out output/stage2
```

Нәтиже: `node_metrics.csv`, `components.csv`, `daily_activity.csv`, `graph_summary.json`. Команда алдымен деректерді тексереді; жарамсыз жиынға есеп шығармайды. Қайта іске қосқанда осы төрт есеп жаңартылады. Кіріс файлдары өзгертілмейді.

Тесттер:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

| 4 | Интерактивті карта, gid іздеу, бағыттар, сүзгілер, клиент карточкасы | Кез келген gid табылып, байланысы және рөлінің негізі көрсетіледі | Іске асырылды |

Нақты датасеттің саны, өрістерінің семантикасы және бақылау шектеулері тексерілді. Белгіленген дұрыс жауаптар (ground truth) жоқ болғандықтан accuracy туралы мәлімдеме жасалмайды. Тексеру дәлелдері: [docs/VERIFICATION.md](docs/VERIFICATION.md). Кілтпен нақты AI сынағы пайдаланушы шешімімен кейінге қалды; негізгі ТЗ нәтижелері API-ге тәуелді емес.

## Шамамен 1 миллион түйінге масштабтау жоспары

Бұл нұсқа 2 248 түйіндік кейсте тексерілді. Миллион түйінде жылдамдық не жад көлемі өлшенген жоқ; төмендегі өзгерістер әлі іске асырылмаған.

| Қазіргі шектеу | Үлкен дерек үшін өзгеріс | Нені тексеру керек |
|---|---|---|
| Үш кесте түгел Pandas жадына оқылады; NetworkX әр түйін/қырды Python объектісімен сақтайды | Parquet-тен тек қажет бағандарды блокпен оқу; жұптық сомаларды бағандық қозғалтқышта есептеу; графты ықшам CSR массивінде сақтау | int64 gid дәлдігі, сомалар мен операциялардың сақталуы, оқшау түйіндердің жоғалмауы |
| Салмақсыз дәл betweenness толық графта шамамен O(V×E) жұмыс істейді | Бекітілген seed-пен түйіндерді іріктеп жуық орталықтық есептеу немесе тек тексерілетін ішкі графта есептеу | Кіші эталонда дәл нәтижемен салыстыру; жуықтық пен рейтинг ауытқуын есепке жазу |
| Әр seed үшін бағытталған жетуді есептеу seed саны өскенде қымбаттайды | Қолжетімділікті компонент/партия бойынша есептеу, bitmap сақтау; карточка жолдарын сұрау бойынша алу | Қолданылған шектеулерді көрсету; жету саны мен толық ақша қозғалысын шатастырмау |
| Louvain және толық граф бір процесс ішінде есептеледі | Ықшам граф қозғалтқышында партиялық қауымдастық есептеу; уақыт бойынша snapshot сақтау | Кластерлердің тұрақтылығы, нұсқаланған параметрлер және ережелермен үйлесуі |
| Қазіргі толық карта бүкіл payload-ты браузерге береді | Серверден gid бойынша 1–2 қадамдық ішкі граф, беттелген көршілер; көрсетілген/толық санды бөлек беру | Миллион түйінді браузерге жібермеу; сүзгі карточканың бастапқы сандарын өзгертпеуі |
| Шектер/нормалау осы жиыннан есептеледі | Уақыт аралығына қарай нұсқаланған конфигурация, есеп кэші және өзгеріс бақылауы | Рейтинг өзгерісін себептерімен тіркеу; белгіленген дерек пайда болса precision@k және талдаушы бағалауы |

Алдымен CPU мен RAM өлшеніп, 10 мың → 100 мың → 1 миллион түйіндік жүктеме сынағы жүргізіледі. GPU кейін өлшенген қажеттілік болса ғана қосылады. **NVIDIA API токені жергілікті GPU жадын немесе граф есептеу кластерін бермейді**: қазіргі интеграция оны тек тілдік түсіндірме үшін қолданады. Қазіргі прототипте жеке ML моделін үйрету қажет емес; болашақ бақыланатын модель үшін белгіленген нәтижелер, уақыт бойынша бөлінген бағалау және дерек ағуын тексеру керек.
