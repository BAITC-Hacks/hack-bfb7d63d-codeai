# MoneyMap · HackAlem AI

MoneyMap — қаржылық мониторинг (AML) талдаушысының жергілікті жұмыс кеңістігі. Үш Parquet файлын ашып, тексеруді қай клиенттен бастау керегін, оған қандай белгілер негіз болғанын және ақшаның кімдер арасында жүргенін зерттеңіз. Нәтиже — бағытталған карта, алты рөлдің түсіндірілетін болжамы, байланыс топтары, тексеру кезегі және үш міндетті CSV.

**Негізгі жұмыс толық жергілікті орындалады.** Граф, рөлдер, басымдық пен анықтама үшін API кілті қажет емес. OpenAI/NVIDIA түсіндірмесі қосымша мүмкіндік ретінде бөлек қосылады. Рөлдер мен ұпайлар кінәлілікті анықтамайды: соңғы бағалауды талдаушы береді.

Ағымдағы өзгерістер мен тексеру қорытындысы: [RELEASE_REVIEW_KK.md](docs/RELEASE_REVIEW_KK.md). Кейс талаптарын толық түсіндіру: [CASE_RESEARCH_KK.md](docs/CASE_RESEARCH_KK.md). Бір беттік [архитектура](docs/architecture.html), бастапқы деректердің [аудиті](docs/INPUT_AUDIT.md) қолжетімді.

## Орнату және іске қосу

Тексерілген орта — **Windows x64, Python 3.14.3**. Компьютерде Python 3.14 x64 орнатылып, `python` командасымен қолжетімді болуы керек. Жоба архивін ашып, оның түбірінде PowerShell іске қосыңыз:

```powershell
python --version
powershell -ExecutionPolicy Bypass -File .\setup.ps1
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Браузерден **http://127.0.0.1:8501** ашыңыз. Бірінші орнатудан кейін тек `start.ps1` жеткілікті. Терминалды ашық ұстаңыз; тоқтату — `Ctrl+C`. Порт бос болмаса:

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Port 8502
```

Негізгі ZIP үшін алғашқы орнатуға интернет қажет; барлық пакет `requirements.txt` ішінде бекітілген. **Offline ZIP Python-ның өзін және ұйымдастырушының бастапқы деректерін қамтымайды.** Оның `wheelhouse` папкасы бар болса, Python 3.14 x64 орнатылған Windows компьютерінде пакеттерді интернетсіз орнатыңыз:

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1 -Wheelhouse .\wheelhouse
powershell -ExecutionPolicy Bypass -File .\start.ps1
```

Бұл wheel жинағы басқа Python нұсқасына, ОС не архитектураға арналмаған. Таза виртуалды ортада `--no-index` арқылы орнату тексерілген; бөлек жаңа Windows орнатылған физикалық компьютердегі сынақ туралы мәлімдеме жасалмайды. Жеке сынақ ортасын `setup.ps1 -VenvDir output\clean-env` арқылы жасауға болады; `start.ps1` әдепкі `.venv` ортасын қолданады. Карта ресурстары жоба ішінде, сыртқы CDN қажет емес.

macOS/Linux үшін төмендегі балама бар, бірақ бұл платформалар бөлек тексерілмеген:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

## Кейсті ашу және алты бөліммен жұмыс

Үш ұйымдастырушы файлын атауларын өзгертпей `data/case/` ішіне салыңыз: `nodes.parquet`, `edges.parquet`, `transactions.parquet`. Сонда **«Кейс деректері · ашу немесе ауыстыру» → «Берілген кейсті ашу»** батырмасы көрінеді. Балама: осы панельде үш файлды бірге жүктеп, **«Файлдарды тексеру»** басыңыз. ZIP-тегі дайын CSV нәтижелері жаңа есептеуге қажет бастапқы Parquet-тің орнын алмастырмайды.

| Бөлім | Не істеуге болады |
|---|---|
| **Шолу** | Клиенттер мен аударым санын көру; «Талдауды бастау» арқылы граф, рөлдер мен топтарды есептеу; күндік айналым, рөлдер құрылымы және алғашқы төрт клиентті қарау |
| **Тексеру кезегі** | Топ-30 мен барлық клиенттерді қарау; рөл бойынша сүзу; ережені және басымдықтың жеті үлесін түсіндіру; клиент жолын таңдап картаға өту |
| **Желі картасы** | Кез келген толық ID-ді табу; 1–2 қадамдық айнала, толық желі немесе бір топты ашу; бағыттар, сүзгілер, клиент карточкасы және бастапқы операцияларды қарау |
| **Кластерлер** | Байланыс топтары, ішкі және сыртқы ағындар, сандық гипотезалар; таңдалған топты картада ашу; параметр өзгергендегі нәтижені салыстыру |
| **Анықтама** | Фактілерден жергілікті анықтама дайындау; TXT/JSON алу; қажет болса қосымша LLM түсіндірмесін бөлек қосу |
| **Деректер және экспорт** | Үш CSV пен JSON/ZIP жүктеу; сапа есебі, бастапқы кестелер және граф көрсеткіштерін тексеру |

Қысқа жұмыс сценарийі:

1. Кейсті ашыңыз. **Шолу → Талдауды бастау** басыңыз. «Тексеру кезегі» ішіндегі «Рөлдер мен басымдықты есептеу» де негізгі талдауды орындайды.
2. **Тексеру кезегі** кестесінен клиент жолын таңдаңыз немесе «Клиент ID» тізімінен клиентті таңдап, **«Желіде ашу →»** басыңыз. Карта қажетті клиентке бірден ауысады.
3. **Желі картасы** бөлімін тікелей ашсаңыз, алдымен **«Картаны дайындау»** басыңыз. Толық ID-ді іздеп, **«Картадан табу»** арқылы кез келген клиентке өтіңіз. Қадам санын және жол бағытын таңдаңыз; қосымша сүзгілер «Карта сүзгілері» ішінде.
4. Картадағы түйінді басыңыз. Төмендегі карточкадан рөл ережесін, кіріс/шығысты, алғашқы/соңғы күндерді, уақыттық қайшылықты, тікелей байланыстарды және операцияларды тексеріңіз. Байланысты клиентке «Желіде ашу →» арқылы ауысуға болады.
5. **Кластерлер → Топты зерттеу → Картада ашу →** арқылы бүкіл топты зерттеңіз. Гипотезаны ішкі/сыртқы сомалармен салыстырыңыз.
6. **Анықтама → Көмекшіге деректерді дайындау** басып, анықтама түрін таңдаңыз. **«Анықтаманы дайындау · API-сыз»** жергілікті есеп береді. Бір клиент туралы тапсырмада «Картадан тексеру» қолжетімді.
7. **Деректер және экспорт → Экспорт** ішінен үш CSV-ді немесе толық ZIP-ті жүктеңіз.

Навигация деректерді қайта жүктемейді. Карта сүзгілері тек көрініске әсер етеді; карточка мен есептелген ұпайлар толық бақыланған жиынға сүйенеді. Жаңа деректер ашылса, бұрынғы граф, рөлдер, карта және анықтама күйі тазартылады. Графты қайта есептеу тәуелді рөлдер мен картаны, рөлдерді қайта есептеу карта мен анықтаманы тазалайды.

**«Демо деректермен тексеру»** — 16 клиент, 15 байланыс, 17 операциядан тұратын толық жасанды мысал. Бүйір панельдегі «Демо және нұсқаулық» ішінен оның ZIP файлын алып, жүктеу сценарийін тексеруге болады. Бұл нақты кейстің дайын жауабы емес.

## Деректер және бақылау шекарасы

| Файл | Міндетті бағандар |
|---|---|
| `nodes.parquet` | `gid`, `depth`, `is_seed` |
| `edges.parquet` | `src`, `dst`, `sum_kzt`, `n_tx`, `depth` |
| `transactions.parquet` | `src`, `dst`, `date`, `sum_kzt` |

Әр файлдың жүктеу шегі — 20 МБ. Валидатор Parquet құрылымын, міндетті/қайталанатын бағандарды, бос мәндерді, дәл int64 идентификаторларды, бірегей клиент пен жұптарды, белгісіз қатысушыларды, оң шекті сомаларды, бүтін операция санын және күндерді тексереді. Транзакцияларды жұп бойынша қосқандағы сома мен сан `edges` кестесіне сәйкес болуы керек. Қате жиынға есептеу жүргізілмейді; жолдар үнсіз жойылмайды.

Нақты кейс: **2 248 клиент, 3 119 бағытталған байланыс, 4 840 операция, 81 бастапқы клиент**. Кезең — **2026-07-01–2026-07-31**, ең аз сома — **5 000 ₸**. Бақыланған айналым — **365 890 012,01 ₸**. Бағытты ескермегенде 35 байланысқан бөлік бар, соның 19-ы оқшау клиент; ең үлкен бөлікте 1 877 клиент бар.

Талдауда міндетті түрде ескерілетін шектеулер:

- Үзінді тек бір банк, бір ай, ≥5 000 ₸ аударым және бастапқы клиенттерден шығатын төрт қадамды қамтиды. Бұл толық қаржылық желі емес.
- **444 клиент 4-қадамда:** олардың кейінгі шығысы жиналмаған. Шығыстың жоқтығы соңғы алушы екенін дәлелдемейді.
- Бастапқы клиенттердің кірісі толық емес. Шығыстың көрінетін кірістен артуы өздігінен аномалия не теріс баланс емес.
- Күн бар, сағат жоқ. Бір күн ішіндегі реттілік пен нақты бір ақшаның бірнеше аударым арқылы өтуі дәлелденбейді.
- Бірдей күн, сома және қатысушылары бар 97 қайталанған жол сақталады: жеке transaction_id болмағандықтан, оларды қате дубликат деп жоюға негіз жоқ.
- Айналым бір ақшаның бірнеше қадамда қайта есептелуін қамтуы мүмкін; ол заңсыз табыс көлемі немесе шоттағы қалдық емес.

`gid` мәндері JavaScript қауіпсіз бүтін сан шегінен үлкен. Браузерге олар **мәтін ретінде** беріледі. CSV-ді Excel-ге импорттағанда `gid` бағанын мәтін түрінде таңдаңыз. `nodes.depth` — клиент алғаш табылған қадам (0–4), `edges.depth` — байланыс табылған қадам (ұйымдастырушыда 1–4); жалпы валидатор соңғысына 0–4 аралығын қабылдайды.

## Рөлдер, басымдық және уақыт

Рөлдер төмендегі ретпен тексеріледі. 4-қадамдағы, оқшау және тек өзіне аударымы бар клиент алдымен `peripheral` болады. Бастапқы клиенттерге кіріс/шығыс қатынасына сүйенген рөл берілмейді.

| Рөл | Әдепкі критерий | Нақты кейстегі саны |
|---|---|---:|
| `coordinator` | Жіберушілер ≥3, алушылар ≥3, жететін өзге бастапқы клиент ≥2; аралық орталықтық оң мәндердің P90 шегінен кем емес әрі >0 | 31 |
| `distributor` | Бірегей алушылар ≥10 | 37 |
| `consolidator` | Қатынас жарамды; жіберушілер ≥5; көрінетін шығыс/кіріс ≤0.3 | 22 |
| `transit` | Қатынас жарамды; екі бағыт бар; шығыс/кіріс 0.8–1.2; барлық шығыс алғашқы кіріс күнінен бұрын жасалмаған | 61 |
| `terminal` | Қатынас жарамды; кіріс >0, шығыс байланысы 0; тек осы кезеңдегі бақылау | 1 071 |
| `peripheral` | Алдыңғы ережелер орындалмаған немесе дерек жеткіліксіз | 1 026 |

**Уақыттық тексеру:** соңғы шығыс күні алғашқы кіріс күнінен ерте болса, `temporal_contradiction=true`. Нақты жиында мұндай **101 клиент** бар. Олардың **8-і** сомаларға ғана сүйенген транзит шартына сәйкес келер еді, бірақ уақыт қайшылығына байланысты транзит рөлі берілмейді. Карточка алғашқы/соңғы кіріс және шығыс күндерін көрсетеді. Күндер бірдей болса реттілік белгісіз; кейінгі күндегі шығыс байқалуы да сол кірістің әрі қарай кеткенін дәлелдемейді.

`role_score` — ережеге сәйкестік ұпайы, калибрленген ықтималдық емес. `priority_score` одан бөлек есептеледі: жинақталу 25%, кіріс сомасы 15%, жіберушілер 15%, аралық орталықтық 15%, бастапқы клиенттерден жету 15%, алушылар 10%, PageRank 5%. Карточка осы жеті үлесті ашады. Жинақталу шегі басымдықтың нормалауына да әсер етеді, сондықтан шекті өзгерткенде тексеру кезегі өзгеруі мүмкін.

## Топтардың ағындары және сезімталдық

Бағытталмаған салмақты проекциядағы Louvain әдісі әдепкі параметрлермен **91 топ** береді; **8 топта** бірнеше бастапқы клиент бар. Негізгі бағытталған граф сақталады. Топ нөмірі ұйым мүшелігін немесе қылмыстық құрылымды білдірмейді.

Әр топтың гипотезасы сандық ағынға сүйенеді: ішкі айналым, топтан тыс кіріс/шығыс, ішкі айналым үлесі, ең ірі ішкі алушы мен жіберушінің үлесі және олардың әртүрлі қарсы тараптары. Өз-өзіне аударым бірнеше клиент арасындағы тарату/жинақтау дәлелі ретінде қолданылмайды. Қазіргі жиында ағын ережесі **31 топқа тарату белгісін**, **41 топқа аралас/жеткіліксіз белгі**, **19 топқа оқшау топ** сипаттамасын береді. Бұл топ гипотезалары жеке клиенттің рөлінен бөлек.

«Ереже өзгерсе, нәтиже қаншалықты өзгереді?» бөліміндегі салыстыру:

| Өзгеріс | Рөлі өзгерген клиент | Топ-30 ішінде сақталғаны | Топ саны |
|---|---:|---:|---:|
| Жинақтаушыға керек жіберуші: 5 → 4 | 17 | 24/30 | 91 |
| Жинақтаушыға керек жіберуші: 5 → 6 | 8 | 25/30 | 91 |
| Louvain масштабы: 1.0 → 0.8 | 0 | 30/30 | 84 |
| Louvain масштабы: 1.0 → 1.2 | 0 | 30/30 | 91 |

Бұл — параметрдің шағын өзгерісіне жергілікті сезімталдық. Ground truth жоқ: accuracy, precision немесе қылмыстық рөлді дұрыс анықтау пайызы өлшенген жоқ. Топ санының бірдей болуы олардың мүшелігі толық өзгермеді дегенді білдірмейді.

## Бір команда: Parquet → үш CSV

Орта орнатылғаннан кейін жоба түбірінде орындаңыз. Деректер басқа жерде болса, `--data-dir` жолын өзгертіңіз:

```powershell
.\.venv\Scripts\python.exe -m moneymap run --data-dir data/case --out output/submission/results
```

| Файл | Бағандар |
|---|---|
| `nodes_roles.csv` | `gid, role, role_score, cluster_id, priority_score, evidence` |
| `clusters.csv` | `cluster_id, n_nodes, n_seed, sum_kzt_internal, top_gids, hypothesis` |
| `top_nodes.csv` | `rank, gid, role, priority_score, why` |

Әр клиентке дәл бір рөл жолы беріледі; ұпайлар 0–1, `evidence` бос емес әрі 200 таңбадан аспайды. Әдепкі кезек — топ-30. `--top-n 50` арқылы өзгертуге болады; ең азы 20, ал шағын демода барлық клиент беріледі. `top_gids` — дәл идентификаторлардан тұратын JSON мәтін тізімі.

`run_report.json` конфигурацияны, нормалау мен шектерді, топ ағындарын, сезімталдық нәтижесін, CLI кіріс SHA-256 хэштерін, кітапхана нұсқаларын және CSV-ге дейінгі уақытты сақтайды. `--config config/roles.json` балама ережелерді жүктейді; белгісіз не жарамсыз параметр қабылданбайды. Қайта орындау шығыс есептерін жаңартады. Жарамсыз кіріс анықталса, жаңа есеп жазылмайды; бұрынғы есептер өзгермейді.

Қосымша командалар:

```powershell
.\.venv\Scripts\python.exe -m moneymap validate --data-dir data/case --output output/validation_report.json
.\.venv\Scripts\python.exe -m moneymap analyze --data-dir data/case --out output/stage2
.\.venv\Scripts\python.exe -m moneymap demo --output-dir data/demo
```

`validate` дерек сапасының есебін, `analyze` — `node_metrics.csv`, `components.csv`, `daily_activity.csv`, `graph_summary.json` файлдарын береді. `demo` жасанды үш файл жасайды, бар файлдың үстінен жазбайды. Шығу кодтары: `0` — сәтті, `1` — тексеру қатесі, `2` — команда/конфигурация/файл/есептеу қатесі.

## Жергілікті анықтама және қосымша LLM

Әдепкі анықтама Python есептеген нақты фактілерден жасалады. Ол **LLM жауабы емес**, API шақырмайды, кілт пен интернетті қажет етпейді. Негізгі рөлдер, топтар және тексеру кезегі де LLM-ге тәуелді емес.

Қосымша провайдерді қолдану үшін `.env.example` үлгісінен өз компьютеріңізде `.env` жасаңыз; бар `.env` болса, оның параметрлерін түзетіңіз. `OPENAI_API_KEY` немесе `NVIDIA_API_KEY` енгізіп, `MONEYMAP_AI_ENABLED=true` орнатыңыз. **Анықтама → Қосымша: LLM түсіндірмесі және баптаулар** ішінен провайдерді таңдап, «API күйін жаңарту» басыңыз. Сұрау тек **«AI түсіндірмесін алу»** батырмасымен жіберіледі. `.env` және кілттер архивке кірмейді.

Конфигурациядағы модельдер: OpenAI `gpt-4.1-mini-2025-04-14`, NVIDIA API Catalog `meta/llama-3.3-70b-instruct`. Нақты аккаунттағы қолжетімділік, қазақша тірі жауап сапасы және төлем бөлек API сынағын қажет етеді; негізгі қабылдау тесттері имитацияланған провайдер жауаптарын қолданады.

Провайдерге тапсырмаға қажет шектеулі фактілер және `C001` сияқты белгілер беріледі; бастапқы Parquet, барлық транзакциялар және толық gid сәйкестік картасы жіберілмейді. Қаржылық көрсеткіштердің өзі нақты дерек болып қалады. JSON құрылымы, факт сілтемелері және сан/белгі шектеулері тексеріледі; бұл мәтіндегі барлық мағыналық тұжырымның ақиқаттығын автоматты растау емес. LLM мәтіні интерфейсте бөлек ашылады, бастапқы фактілермен тексеріледі.

Әдепкі жергілікті шек — 20 сұрау, 200 000 есепке алынған/резервтелген токен, OpenAI үшін $1 есептік шығын. Бұл провайдер аккаунтының балансы немесе төлем шегі емес. NVIDIA бағасы белгісіз болғанда ақша құны болжанбайды; сұрау/токен шектері қолданылады. Екі провайдер қатар шақырылмайды, автоматты қайталау жоқ. Кілттер браузер мен журналға шығарылмайды.

## Қабылдауды тексеру және архив

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe scripts\verify_submission.py --data-dir data/case --out output/submission/results
.\.venv\Scripts\python.exe scripts\package_submission.py
```

Тәуелсіз қабылдау скрипті шикі файлдардан есепті екі рет шығарып, схемаларды, барлық gid қамтылуын, ұпайларды, evidence ұзындығын, топ сомаларын, кезекті және 300 секунд талабын тексереді. Үш CSV-дің байттары мен бастапқы файл хэштері салыстырылады. CLI ішіндегі Python socket/DNS шақырулары бұғатталады; бұл физикалық желі ажырату сынағы емес. Ағымдағы нақты тест саны мен уақыт өлшемдері [шығарылым есебінде](docs/RELEASE_REVIEW_KK.md) беріледі.

Offline архивті де құрастыру үшін сәйкес ортада алдын ала барлық wheel пакетін дайындаңыз:

```powershell
.\.venv\Scripts\python.exe -m pip download --only-binary=:all: -r requirements.txt --dest output/wheelhouse
.\.venv\Scripts\python.exe scripts\package_submission.py --wheelhouse output/wheelhouse
```

Дайын архивтер `output/submission/` ішінде. Оларға код, құжаттар, тесттер, жергілікті карта ресурстары, үш дайын CSV, JSON есептері және SHA-256 manifest кіреді. Offline нұсқа бекітілген wheel пакеттерін қосады. **Шикі Parquet, Python, `.env`, кілттер, виртуалды орта және шығын журналы қосылмайды.** Басқа компьютердегі нақты демоға үш ұйымдастырушы файлын бөлек алып барыңыз. Дайын CSV-де нақты gid бар; архив жергілікті хакатон тапсыруына арналған.

## Миллион түйінге өсу жоспары

Бұл нұсқа 2 248 түйіндік кейске арналған; миллион түйіннің жылдамдығы мен жады өлшенбеген. Үлкен дерекке мына өзгерістер қажет:

| Қазіргі шектеу | Келесі қадам |
|---|---|
| Pandas пен NetworkX кестелерді/графты жадта ұстайды | Parquet-ті баған/блок бойынша оқу, ықшам CSR графын қолдану; int64 дәлдігі мен сомаларды сақтау |
| Дәл betweenness есептеу қымбат | Бекітілген кездейсоқ seed-пен жуық есеп не қажетті ішкі граф; шағын эталонмен рейтинг айырмасын өлшеу |
| Әр бастапқы клиенттен қолжетімділікті есептеу өседі | Партиялық есеп, bitmap, карточка жолдарын сұрау бойынша алу |
| Louvain бір процесте орындалады | Ықшам граф қозғалтқышы, нұсқаланған параметрлер мен кезеңдік snapshot |
| Толық карта браузерге толық payload береді | Серверден 1–2 қадамдық ішкі граф пен беттелген көршілер; толық/көрсетілген санды бөлу |
| Шектер осы жиынға тәуелді | Уақыт бойынша конфигурация мен рейтинг өзгерістерін тіркеу; белгіленген дерек пайда болса precision@k және талдаушы бағалауы |

Алдымен 10 мың → 100 мың → 1 миллион түйінде CPU, RAM және уақыт өлшенеді. GPU өлшенген қажеттілікке қарай қарастырылады. NVIDIA API токені жергілікті GPU жады немесе граф есептеу кластерін бермейді; қазіргі адаптер тілдік түсіндірме үшін қолданылады.
