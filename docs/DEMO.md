# MoneyMap: 5 минуттық тірі демо

Бұл сценарий банк қаржылық мониторингі маманына арналған құралды көрсетеді. Мақсат — «2 248 клиенттің қайсысын алдымен тексереміз және неге?» деген сұраққа есептелген фактілермен жауап беру. Рөлдер — тексеру гипотезалары; жүйе кінәлілікті анықтамайды және шоттарды бұғаттамайды.

Мысалдар 2026-09-23 күні `data/case` ішіндегі нақты үш Parquet файлын `.venv` Python арқылы қайта оқып, `analyze_dataset` және `classify_graph` функцияларымен есептелді. Бұл gid-тер тек көрсетілім үшін таңдалған: алгоритмде олар үшін арнайы ереже жоқ. Төмендегі мәндер әдепкі конфигурацияға тиесілі. Дерек не шектер өзгерсе, жаңадан шыққан есепті қолданыңыз.

## Көрсетілімге дейін

1. README бойынша тәуелділіктерді орнатыңыз. Нақты `nodes.parquet`, `edges.parquet`, `transactions.parquet` файлдары `data/case` ішінде болсын. Демо деп белгіленген 16 клиенттік жасанды жиынды нақты кейспен шатастырмаңыз.
2. Жоба түбіріндегі PowerShell терезесін CLI үшін дайындаңыз. Екінші терминалда `powershell -ExecutionPolicy Bypass -File .\start.ps1` іске қосып, браузерде `http://127.0.0.1:8501` ашыңыз. Қолданыстағы порт бос болмаса, README-дегі `-Port` параметрін пайдаланыңыз.
3. Осы құжаттағы төрт gid-ті көшіруге ыңғайлы күйде ұстаңыз. CLI нәтижесі және браузер екі бөлек интерфейс арқылы бір есептеу модулін пайдаланады; веб CLI CSV файлдарын автоматты оқымайды.
4. Нақты API пайдаланушының сұрауы бойынша кейінге қалдырылған. Кілт енгізбеңіз, сыртқы AI сұрауын жібермеңіз. Кілтсіз жергілікті анықтаманы ғана көрсетіңіз.
5. Тірі уақытты алдын ала ойдан айтпаңыз. Пайплайнның сол іске қосудағы уақытын терминалдан және `run_report.json` ішіндегі `raw_to_csv_seconds` өрісінен оқыңыз. Бұл уақытқа бастапқы орнату мен браузерді салу кірмейді.

Сол жақ мәзірдегі жұмыс реті: **Шолу → Тексеру кезегі → Желі картасы → Кластерлер → Анықтама → Деректер**. Соңғы бөлім интерфейсте «Деректер және экспорт» деп көрсетіледі. Бет ауыстыру жүктелген кейс пен дайын есептерді сақтайды.

Талдау шегі: 2026 жылғы шілде, банк ішіндегі аударымдар, кемінде 5 000 ₸, бастапқы клиенттерден төрт буын. Нәтиже толық шот балансы немесе қылмыстық топтың дәлелденген құрамы емес.

### 00:30–01:00 — бір командадан міндетті нәтижелер

**Тікелей орындаңыз:**


`Stage 3 reports` — команданың қазіргі атауы; бұл толық рөл/кластер/басымдық пайплайнының нәтижесі. `<…>` — түсіндірме, күтілетін тірі санның орнына қолданылмайды.

**Айтыңыз:** «Барлық 2 248 клиентке рөл мен кластер берілді. Топта 30 клиент бар, демек ТЗ-дегі кемінде 20 талабы орындалды. Үш CSV және есептеу параметрлері бар JSON жаңадан жасалды».

Файлдар: `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv`, `run_report.json`. Қайта іске қосу осы шығыс файлдарын жаңартады; бастапқы Parquet өзгермейді. Уақытты экраннан оқып, ТЗ-дегі 300 секунд шегімен салыстырыңыз.

## Жюри басқа gid атаса: 1 минуттық жауап

1. **«Желі картасы»** іздеуіне толық gid енгізіп, **«Картадан табу»** басыңыз. Бұл іздеу барлық клиент бойынша орындалады.
2. Карточкадан рөл, **«Орындалған ереже»**, нақты көршілер/сомалар және **«Ұпайдың құрамы және қосымша көрсеткіштер»** бөлімін көрсетіңіз.
3. Seed, төртінші буын немесе оқшау клиент болса, шектеуін бірінші айтыңыз.
4. **«Тікелей байланыстар»**, **«Жеке операциялар»**, қажет болса **«Бастапқы клиент жолдары»** арқылы бастапқы негізді ашыңыз. Карта сүзгілері карточкадағы толық көрсеткіштерді өзгертпейді.

## Қосымша сұраққа: уақыт пен шектердің тұрақтылығы

Клиент карточкасындағы **«Аударым күндері»** кірістің және шығыстың алғашқы/соңғы күндерін көрсетеді. Егер барлық шығыс алғашқы кірістен бұрын болса, `transit` берілмейді. Осы түзету әдепкі 69 транзит кандидаттың **8-ін** алып тастады: қазір **61 transit**, **1 026 peripheral**. Бір күнге сәйкес келгенде реттілік белгісіз күйінде қалады; уақыттық қайшылықтың жоқтығы дәл сол ақшаның өткенін дәлелдемейді.

Қосымша мысал: `100000000922570100` — кіріс **47 101 ₸**, шығыс **50 000 ₸**. Сомалар қатынасы жақын, бірақ соңғы шығыс **2026-07-04**, алғашқы кіріс **2026-07-15**. Сондықтан қазір `peripheral`, рөл ұпайы **0,3**. «Шығыс кірістен кейін болды» деп қате түсіндірме жасалмайды.

**«Тексеру кезегі»** не **«Кластерлер»** бетіндегі **«Ереже өзгерсе, нәтиже қаншалықты өзгереді?»** бөлімін ашыңыз. Ол жинақтаушының жіберуші шегін және Louvain параметрін өзгерткенде рөл саны, топ саны мен топ-30 сәйкестігін салыстырады. Бұл бірнеше жергілікті сценарийдің сезімталдық тексеруі; accuracy немесе барлық параметрге тұрақтылық кепілдігі емес. Экрандағы ағымдағы сандарды оқыңыз.

Оқшау клиентке қосымша мысал: `100000000456947100` — seed, 0 байланыс, 0 операция, `peripheral`, рөл ұпайы **0,100**, басымдық **0**, кластер **73**. Клиент жойылмаған; «дерек жоқ» деген жағдай есепте сақталған.
