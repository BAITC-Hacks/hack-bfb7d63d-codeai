# 2-кезең: граф және бақыланған көрсеткіштер

Бұл кезең банк талдаушысына «Кім кімге аударған?», «Қанша кіріп/шыққан?», «Қандай seed-ден осы клиентке жетуге болады?», «Қай күндері қозғалыс болған?» деген сұрақтарға тек берілген деректермен жауап береді. Рөлдер мен тексеру басымдығы 3-кезеңде есептеледі.

## Құрылған граф

NetworkX `DiGraph`: алдымен барлық `nodes.gid`, содан кейін `src → dst` байланыстары. Түйінде `depth`, `is_seed`; байланыста `sum_kzt`, `n_tx`, `discovery_depth` бар. `nodes.depth` пен `edges.depth` алмастырылмайды. Идентификаторлар Python/int64 дәлдігімен сақталады, браузерге мәтін ретінде беріледі.

## Клиент көрсеткіштері

| Баған | Есептеу және мағынасы |
|---|---|
| `in_deg`, `out_deg` | Өзге бірегей жіберушілер/алушылар саны; клиенттің өзі есепке кірмейді |
| `in_kzt`, `out_kzt` | Көрінетін кіріс/шығыс сомалары |
| `in_tx`, `out_tx` | Кіріс/шығыс операциялары саны |
| `component_id` | Бағыт ескерілмегендегі байланысқан бөлік; Louvain кластері емес |
| `pagerank` | Бағытталған, ақша сомасымен салмақталған PageRank; alpha=0.85, tol=1e-12, max_iter=1000 |
| `betweenness` | Нақты нормаланған бағытталған аралық орталықтық; ең қысқа жол байланыс саны арқылы анықталады, ақша сомаcы қашықтық емес |
| `reachable_seed_count` | Түйінге бағытталған жолмен жететін өзге seed саны; түйіннің өзі есепке кірмейді |
| `min_seed_hops` | Кез келген seed-ден ең аз қадам; seed үшін 0, жол жоқ болса бос |
| `observed_flow_ratio` | `out_kzt / in_kzt`; кіріс 0 болса бос |
| `ratio_usable` | Кірісі бар, seed емес және depth<4 клиент үшін true; бұл толық баланс дегенді білдірмейді |
| `truncated_by_depth` | depth=4, кейінгі қозғалыс осы үзіндіде толық көрінбейді |
| `is_isolated` | Ешбір бақыланған байланысы жоқ; өзіне аударымы бар клиент оқшау емес; мұндай клиенттер жойылмайды |
| `active_days`, `in_active_days`, `out_active_days` | Кез келген/кіріс/шығыс операциясы бар бірегей күндер |
| `first_date`, `last_date` | Бақыланған бірінші/соңғы белсенді күн; операция болмаса бос |
| `temporal_eligible_in_tx` | Ең соңғы бақыланған күннен кемінде 2 күн бұрынғы кіріс операциялары саны |
| `next_out_1_2d_share` | Сол кірістердің ішінде клиенттің қатаң кейінгі 1–2 күнде шығысы байқалғандарының үлесі |
| `mean_next_out_days` | Есепке жарамды кірістен ең жақын қатаң кейінгі шығыс күніне дейінгі шартты орташа уақыт |

Өзіне аударым `in_deg`/`out_deg` мәндерін өсірмейді, бірақ графта, `in_kzt`/`out_kzt`, `in_tx`/`out_tx`, PageRank және ішкі айналым есептерінде сақталады. Сондықтан тек өзіне аударған клиент үшін екі дәреже 0 болғанымен, `is_isolated=false` болады.

Бөліктер алдымен көлемі кемуімен, тең болса ең кіші gid арқылы реттеліп, 1-ден нөмірленеді. Кіріс кестелердің жол ретін өзгерту есептің мағынасын өзгертпейді.

## Уақыттық белгіні дұрыс түсіну

Бастапқы дата тек күнді береді. Сондықтан бір күндегі кіріс пен шығыстың реті жорамалданбайды. Мысалы, 10 шілдедегі кіріс үшін бірінші шығыс 12 шілдеде болса, 1–2 күндік белгі оң; бірінші шығыс 13 шілдеде болса, теріс. 10 шілденің өзіндегі шығыс есепке алынбайды.

Мысалы, бақылаудың соңғы күні 31 шілде болса, үлеске тек 29 шілдеге дейінгі кірістер кіреді; 30–31 шілдеде толық екі күндік бақылау жоқ. Бөлімге кіретін операция саны 0 болса, үлес те бос беріледі. Қайталанатын операциялар жойылмайды.

`mean_next_out_days` тек кейінгі шығысы байқалған, есепке жарамды кірістерден есептеледі; 2 күннен ұзақ аралықтар да кіреді. Кейінгі шығысы жоқ кіріс үлестің бөліміне кіреді, бірақ орташа уақытқа кірмейді. Сондықтан бұл барлық қаражаттың орташа ұсталу мерзімі емес. Бір шығыс бірнеше алдыңғы кірістің белгісіне әсер етуі мүмкін; ақша сомалары сәйкестендірілмейді.

Seed жолдары — ең көбі бес бастапқы клиенттен қысқа бағытталған құрылымдық жол. Қадамдардың күн бойынша бірінен кейін бірі болғанына немесе дәл сол ақшаның өткеніне дәлел емес.

## Нәтиже файлдары

`python -m moneymap analyze --data-dir data/case --out output/stage2`:

- `node_metrics.csv`: әр клиенттің жоғарыдағы көрсеткіштері;
- `components.csv`: component_id, n_nodes, n_edges, n_seed, sum_kzt_internal, is_isolated;
- `daily_activity.csv`: date, sum_kzt, n_tx, n_senders, n_receivers; бақыланған алғашқы/соңғы күн аралығы, бос күн болса нөлмен толтырылады;
- `graph_summary.json`: жиынтық сандар, әдістер, шектеулер және есептеу уақыты.

CSV UTF-8 BOM түрінде жазылады. Ұзын gid-ді Excel-ге мәтін ретінде импорттау керек. Бұл файлдар ТЗ-дегі `nodes_roles.csv`, `clusters.csv`, `top_nodes.csv` файлдарын алмастырмайды; олар 3-кезеңде жасалады.

## Бұрынғы нақты кейспен тексеру жазбасы

Төмендегі сандар бұрын берілген компьютердегі аудиттен сақталған. Олар ағымдағы көшірмеде нақты файлдар бар екенін растамайды; өзіндік аударымға қатысты жаңартудан кейін нәтижелерді нақты кіріспен қайта есептеу қажет.

2 248 клиент, 3 119 байланыс, 4 840 операция, 81 seed; 35 бөлік, оның 16-сында байланыс бар, 19-ы оқшау клиент; ең үлкен бөлік — 1 877 клиент. Ең көп бірегей жіберуші — 24, алушы — 116. Бақыланған жалпы айналым — 365 890 012,01 ₸.

Кіріс сомаларының қосындысы, шығыс сомаларының қосындысы, компоненттердің ішкі сомасы және күндік сомалар жалпы айналыммен сәйкес келеді. Барлық клиент сақталады; PageRank қосындысы ≈1. Қысқа белгілі графтармен цикл, бірнеше seed, оқшау түйін, дәл үлкен gid, уақыт шекарасы, бос аударымдар және жол ретін ауыстыру тексеріледі.
